Key observation: Both sessions found the same answer. The difference is efficiency of discovery. Context Signals eliminates the grep-loops and full-file reads by providing a structural map first. The signal store acts as pre-computed discovery, so the agent navigates directly to the relevant code.

5. What This Session Replay Demonstrates

  1. Signal-guided navigation eliminates grep loops. Instead of "grep → read → grep → read", the agent makes one signal search call and follows the results.
  2. Graph edges provide the multi-hop bridge. The call edge from dispatch_to_provider to call_openai is stored at index time. The agent doesn't need to grep for the next link in the chain.
  3. Targeted reads replace full-file reads. With line numbers from signals, the agent reads 1,800 chars instead of 6,500 for the provider file.
  4. Upfront indexing cost is amortized. The index took ~1.5s to build for LiteLLM (350K chars). Across 15 benchmark queries, the indexing cost is recouped by query 6.
  5. Same correctness, less waste. Both agents found the complete dispatch chain. Context Signals used 91.8% less context to get there.

6. How to Reproduce

# 1. Clone LiteLLM
git clone https://github.com/BerriAI/litellm.git /tmp/litellm

# 2. Index with Context Signals
npx context-signals-mcp signals-scan --root /tmp/litellm

# 3. Search for provider dispatch
npx context-signals-mcp signals-search --query "provider dispatch"

# 4. Read targeted file range
# (use the file:line returned by the search)

For the grep-only baseline, use standard tools:

# 1. Search for dispatch
grep -r "dispatch" /tmp/litellm --include="*.py" | wc -l

# 2. Read candidate files
cat /tmp/litellm/litellm.py
cat /tmp/litellm/provider_dispatcher.py

# 3. Search again for the next link
grep -r "call_openai" /tmp/litellm --include="*.py"

# 4. Read the next file
cat /tmp/litellm/providers/openai.py

The ground-truth data in benchmarks/projects/litellm/ground-truth.json defines the expected answers used in this replay.

7. Limitations of This Replay

  • Manual reconstruction. This replay was reconstructed from benchmark ground-truth data and logs, not captured from a live agent session.
  • Single query. One replay cannot represent all query types. Simple queries (e.g., "find the upload route") show smaller gaps; architectural queries show larger gaps.
  • Cold start excluded. The indexing cost (~1.5s for LiteLLM) is amortized across queries. The first query after cold start does not benefit from signals.
  • Idealized agent behavior. Real agents may deviate from the optimal path shown here due to prompt variation or tool-choice randomness.
  • Targeted file read not yet an MCP tool. The targeted line-range read shown here is the recommended next step, not a built-in tool in v1.1.2.

Despite these caveats, the structural pattern is real and consistent across all 90 benchmark runs (v0.8). See the full research report for aggregate data.
