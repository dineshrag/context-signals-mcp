# v0.6 Embeddings Experiment Results

**Date**: 2026-05-09
**Version**: v0.6
**Status**: Experiment complete - embeddings remain optional/off by default

---

## Executive Summary

Local embeddings (all-MiniLM-L6-v2, 384 dimensions) were tested as an optional reranker on top-k BM25+graph results.

**Decision**: Embeddings improve LiteLLM significantly (+26.7%) but not DRF (+6.7%). Per your decision rule, embeddings stay as optional toggle, off by default.

---

## Experiment Configuration

**Flow**: BM25 + graph → top 20 → embeddings rerank → top 5

**Model**: Xenova/all-MiniLM-L6-v2 (384 dimensions, ~90MB)

**Blend weight**: 0.3 (30% embedding score, 70% original score)

| Hit Rate | 6.7% (1/15) | 33.3% (5/15) |
| Improvements | - | 4 queries |

**Improved queries**:

**Analysis**: Embeddings bridge the semantic gap where "chat" maps to "completion" but lexical search fails. This is exactly the use case embeddings are designed for.

## Decision Breakdown

### LiteLLM: WORTH IT
- Improvement: 6.7% → 33.3% (+26.7%)
- Threshold: >20% → **PASS**
- Justification: Embeddings correctly map "OpenAI provider" to the provider class when lexical search fails. This is the intended use case.

### DRF: NOT WORTH IT
- Improvement: 33.3% → 40% (+6.7%)
- Threshold: >15% → **FAIL**
- Justification: Most failures are `missing_signal_kind` (8/9). Embeddings cannot conjure signals that don't exist in the index.

### Flask/FastAPI: Already strong baselines
- Flask went from 73.3% to 100%, but baseline was already acceptable
- FastAPI went from 73.3% to 80%, marginal improvement

## Failure Analysis Post-Embeddings

### LiteLLM (10 remaining misses)
- 5 queries still MISS due to `missing_graph_edge` (fileContains check fails)
- Embeddings help with semantic matching but can't fix file path gaps

### DRF (9 remaining misses)
- 7 queries still MISS due to `missing_signal_kind` (fixture gap, embeddings can't help)
- 1 query MISS due to `lexical_mismatch`
- 1 query MISS due to `query_too_semantic`

### FastAPI (3 remaining misses)
- 1 query MISS due to `query_too_semantic`
- 2 queries MISS due to `lexical_mismatch`

## Recommendation

**Keep embeddings as optional toggle, off by default.**

**Justification**:
1. LiteLLM improvement (+26.7%) justifies optional toggle for users who work with LLM provider code
2. DRF improvement (+6.7%) does not meet the 15% threshold
3. No regressions across all 4 projects
4. Latency overhead is acceptable (2-4ms per query)
5. Model size (90MB) is reasonable for optional feature

**Configuration**:
```typescript
interface EmbeddingsConfig {
  enabled: boolean  // default: false
  modelName: string  // default: "Xenova/all-MiniLM-L6-v2"
  blendWeight: number  // default: 0.3
  topK: number  // default: 20
}
```

## v0.6 Conclusion

**Embeddings improve semantic matching where lexical + graph fail.**

**When embeddings help**:
- Query uses different terms than indexed symbols ("chat" vs "completion")
- Architectural queries that need to understand project structure
- Multi-hop queries that require understanding relationships

**When embeddings don't help**:
- Missing signals (DRF `missing_signal_kind` failures)
- File path gaps (LiteLLM fileContains failures)
- Lexical mismatches that require exact term matching

**Final decision**: Embeddings are valuable for LiteLLM-style codebases but not broadly justified. Offer as optional toggle with clear documentation of use cases where it helps.
